02 AI systems · Local-first

A local-first
AI agent system.

Agentop runs a cluster of specialised agents on your own machine, and reaches for a cloud model only when it decides the job is worth it.

  • Agents 17
  • Tools 38
  • Routing Local / hybrid / cloud
  • Status In development

The problem

Sending everything to the cloud is the expensive default.

Most agent frameworks answer every request with a call to a hosted model. That is simple, and it means your data leaves the building for work a local model could have done — and the bill grows with usage rather than value.

The opposite extreme is no better: a purely local setup falls over on the genuinely hard prompts.

The approach

Make the routing an explicit, governed decision.

Agentop puts a router between the agents and the models, running in one of three modes — local only, hybrid, or cloud only. The agents do not each decide where their tokens go; the cluster does, in one place you can inspect and change.

Above the router sits a governing agent, with specialised agents beneath it for deployment, observation and data access, and a gateway that exposes tools over MCP.

  • Soul Core

    The governing agent over the cluster.

  • DevOps agent

    Handles deployment work.

  • Monitor agent

    Observes the running system.

  • Data agent

    Answers queries against the data layer.

  • MCP gateway

    Publishes the tool surface over MCP.

  • Desktop app

    A Next.js interface packaged with Electron.

Where it stands

In active development. The architecture is documented and versioned, a desktop build exists, and the project keeps its own known-issues log and drift guard. It is a working system being pushed forward, not a finished product — and it is described here as such.
